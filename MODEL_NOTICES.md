# RajTune offline stem separation — model notices

RajTune downloads the KUIELab MDX-Net leaderboard-B ONNX checkpoint archive only when the user first starts separation. The archive is `onnx_B.zip` from the authors' Zenodo record (DOI [10.5281/zenodo.6513062](https://doi.org/10.5281/zenodo.6513062)); the record identifies the trained parameters as CC BY 4.0. Attribution: Minseok Kim, Woosung Choi, Jaehwa Chung, Daewon Lee, and Soonyoung Jung, “KUIELab-MDX-Net: A Two-Stream Neural Network for Music Demixing” (2021), https://doi.org/10.5281/zenodo.6513062.

The inference architecture and leaderboard-B configuration are based on the authors' [MIT-licensed `kuielab/mdx-net-submission` repository](https://github.com/kuielab/mdx-net-submission/tree/leaderboard_B). RajTune uses four separate B models (bass, drums, other, vocals). We verify the downloaded ZIP's Zenodo MD5 and each extracted ONNX file's SHA-256 before inference. The downloaded ZIP is 103,131,501 bytes (~103 MB); extracted models occupy about 111 MB (106 MiB). The download is on demand, never bundled in the APK. The ZIP is checked before extraction, each model is SHA-256 checked before use, then verified models are retained in app-private storage and reused offline. A failed attempt can be retried; valid cached models are reused. Extraction temporarily needs space for both the ZIP and extracted files (~214 MB). Separation additionally copies the selected file to cache, creates float32 stereo PCM (~21.2 MB per audio minute), and writes four 16-bit stereo WAV stems (~42.3 MB per audio minute total), then removes temporary input/PCM files. Actual free-space needs vary with the source file and duration.

The checkpoints are from the 2021 Music Demixing Challenge. They are not a claim of studio-grade quality; separation artifacts, leakage and device-dependent processing time are expected. Model weights are not bundled into the APK.

## Smoke-test evidence

The archive MD5 and the four extracted model SHA-256 digests were checked against the files used for the implementation. ONNX metadata reports input/output tensors `[1, 4, 2048, 256]` for bass, other and vocals, and `[1, 4, 2048, 128]` for drums. A CPU smoke test ran each model on a 2.4-second generated stereo mixture (not a real song or listening test): all four outputs had the expected tensor shape and finite samples; the four output WAVs were each 423,404 bytes. Total inference time was about 37.6 seconds on the test host, not an Android-device benchmark. This only demonstrates real model execution and file generation; it does not measure separation quality or establish professional/studio sound. The repository contains no real-song listening-quality test or Android device benchmark yet.
